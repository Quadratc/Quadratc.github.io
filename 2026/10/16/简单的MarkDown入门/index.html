开始之前：到底什么是 MarkDown？

日常中的 Markdown 应用

在 AI 软件刚刚兴起的时候，我在网上学习如何更高效地让 AI 生成一个 PPT，当时一个视频给出了一个方法：让 Deepseek 以 “MarkDown” 格式生成一个 PPT 大纲。当时我并没有接触 Markdown 语言，只是根据视频中的方法生搬硬套。

可在我后来使用 AI 软件的过程中，我发现 AI 软件所输出的内容格式会有一瞬间以类似 “*”、”~~”、”||” 这样的符号所包裹，然后瞬间转化为优美的格式画面。所以正如这个 Blog 的简介所说，我将在这里介绍一些当代前沿的计算机知识，我决定不从编程语言和数据结构开始，而是直接从 Markdown 语言开始。因为它更适合不同行业的人所使用，包括但不限于：文档编写、代码注释、PPT 制作等。

AI 时代，Markdown 成了大模型最爱的”通用语言” —— ChatGPT 用它输出，Cursor 用它写文档，连提示词都开始用 Markdown 写了。

同时，本 Blog 也是使用部分 Markdown 语言与 HTML 语言编写的。

为什么 Blog 要使用它？

专注内容

纯文本

任何编辑器都能打开，二十年后也不会打不开

格式稳定

不会像 Word 那样，换个电脑排版就乱掉

到处通用

GitHub、知乎、笔记软件、你的博客，全都认它

Markdown 的来历

Markdown 是一种轻量级标记语言，由约翰·格鲁伯（John Gruber）于 2004 年创建，旨在用易读易写的纯文本格式编写文档，并转换为 HTML、Word、图像、PDF、Epub 等多种格式的文档。

如何编写 Markdown 文档？

安装 Markdown 编辑器

由于 Markdown 文档的使用越来越频繁，选一款自己顺手的 Markdown 编辑器就很重要。当前网上的 Markdown 编辑器非常多，有纯写作的、有知识管理的、有在线协作的、也有程序员顺手用的等等。”到底该用哪个，哪个更好”并没有统一的选择标准，其实自己习惯使用的，对于自己来说就是最好的。

单独对于 Markdown 编辑器，首推以下两款软件：

Typora闭源$14.99 一次性买断（有试用期）

"用过 Typora 之后，再也回不去分栏预览的编辑器了——它让 Markdown 写作变成了一种享受。"

经典的所见即所得 Markdown 编辑器，输入语法即时渲染，界面极简优雅。支持数学公式、流程图、表格，主题丰富可自定义 CSS。缺点是纯单文件编辑器，没有笔记管理、没有移动端、没有 AI 功能。适合纯粹追求写作体验的人。

官网https://typora.io/
为何推荐 Typora？写完之后即时看到效果，没有分栏预览，没有笔记管理，没有移动端，没有 AI 功能——适合纯粹追求写作体验的人。

而对于有一定编程基础和需求的人，当然是使用 VS Code 更合适：

Visual Studio Code开源免费

"它不是专门的 Markdown 编辑器，但 90% 的程序员都在用它写 Markdown——因为没必要再装一个。"

通过 Markdown All in One、Markdown Preview Enhanced 等插件，秒变强大的 Markdown 编辑器。集成 Git、终端、Copilot AI，插件生态全球第一。缺点是界面偏技术向，不是所见即所得，分栏预览对纯写作者不够友好。

官网https://code.visualstudio.com/
为何推荐 Visual Studio Code？作为一个专业的代码编辑器，它集成了 Git、终端、Copilot AI 等功能，适合有一定编程基础的人。

至于其他 Markdown 编辑器，在本文中不再过多介绍，可以根据个人习惯选择。

ps. 我自己的选择其实我本人习惯使用 Trae 作为 Markdown 编辑器。它作为字节跳动出品的带有 AI 功能的 IDE，可以说集合了以上两种编辑器的功能和优点，无论是编写代码，还是 Markdown 写作，都可以有很舒服的体验。

学习 Markdown 语法

本部分将介绍 Markdown 的基本语法，包括：标题、段落与换行、文字格式、列表、链接、图片、引用、代码、表格、分割线和转义字符；最后再拓展讲讲用 Markdown 写博客时常见的两样东西，并附上一份速查表和常见错误清单。

三条铁律（记住这三条，能避开九成的坑）

1

符号和文字之间要留一个空格。# 标题 正确，#标题 不生效。

2

用空行分段。段落之间空一行；只按一次回车的换行，大多数情况下不会显示成换行。

3

存成 UTF-8 编码。否则中文会变成乱码。

标题

在文字前面加井号 #，一个井号是一级标题，两个是二级，最多六个。

写这样
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
长这样

一级标题

二级标题

三级标题

四级标题（字号比正文略大）

注意井号后面必须有一个空格，#标题 不会被识别成标题。小提示：独立写文档时用 # 作为文章大标题；而在 Hexo 等博客系统中，大标题通常由文件头部的 title 提供，正文从 ## 开始即可。

段落与换行

写这样
这是第一段。
···· 空一行 ····
这是第二段，中间空了一行。
这一行结尾有两个空格··
所以这里换行了。
长这样

这是第一段。

这是第二段，中间空了一行。

这一行结尾有两个空格
所以这里换行了。

最容易踩的坑很多人这么写：
第一行
第二行
结果网页上显示成「第一行 第二行」（挤在一行），因为 Markdown 认为这只是一个段落的自然折行。

想让它们真的分成两行，三个办法：
  • 中间空一行（变成两个段落，会带段间距）
  • 行尾敲两个空格再回车（只换行，不加段间距）—— 但两个空格看不见，容易忘
  • 行尾写 <br>（最直观，推荐）

文字格式

写这样
**粗体文字**
*斜体文字*
***又粗又斜***
~~删除线~~
`行内代码`
长这样

粗体文字

斜体文字

又粗又斜

删除线

行内代码

小技巧星号 * 和下划线 _ 都能表示斜体（*斜体* 和 _斜体_ 效果一样）。但中文里建议统一用星号，因为下划线在英文单词里容易和普通下划线混淆。

列表

无序列表

用 -、* 或 + 开头（后面要有空格）。

写这样
- 第一项
- 第二项
  - 缩进两格是子项
  - 再来一个子项
- 第三项
长这样
  • 第一项
  • 第二项
    • 缩进两格是子项
    • 再来一个子项
  • 第三项

有序列表

写这样
1. 第一步
2. 第二步
3. 第三步
长这样
  1. 第一步
  2. 第二步
  3. 第三步

小知识：序号写错了也没关系，就算全写 1.，渲染时也会自动按 1、2、3 排列。

任务清单（部分平台支持）

写这样
- [x] 已完成的事项
- [ ] 待办的事项
长这样
  • ✓已完成的事项
  • 待办的事项
GitHub、Typora 等支持；部分平台不一定渲染成复选框。

链接

写这样
[点我去百度](https://www.baidu.com)
<https://www.baidu.com>
[带提示的链接](https://www.baidu.com "鼠标悬停会显示这句")
长这样

点我去百度

https://www.baidu.com

带提示的链接

方括号里是显示的文字，圆括号里是网址。用尖括号包住网址，也会自动变成可点的链接。

图片

跟链接很像，只是前面多一个感叹号 !。

写这样
![图片说明](images/photo.png)
[![头像](https://example.com/avatar.png)](https://example.com)
长这样

第二行是「点图片跳转」：把图片语法套进链接语法里。
图片路径怎么写？图片地址支持两种形式：网络图片直接写完整网址（如 https://example.com/photo.png）；本地图片写相对于当前文档的路径（如 images/photo.png），在网站中以 / 开头则表示「从网站根目录算起」。

常见做法是把图片统一放到图床（专门托管图片的服务）或项目的图片文件夹里，再复制它的链接地址。文件名别用空格和中文特殊符号，用英文或拼音最保险，比如 my-photo-01.png，同时注意路径区分大小写。

引用

在行首加 >（大于号）加空格。

写这样
> 排除一切不可能的，
> 剩下的即使再不可思议，
> 那也是真相。
···· 空一行 ····
> 第一层引用
>> 第二层引用（嵌套）
长这样
排除一切不可能的，
剩下的即使再不可思议，
那也是真相。
第一层引用
第二层引用（嵌套）

写名言警句、引述别人的话时很好用 —— 比如福尔摩斯的那句名言。

代码

行内代码

用一对反引号 ` 包住，适合写命令名、文件名、变量名。

写这样
输入 `python hello.py` 命令
长这样

输入 python hello.py 命令

代码块

用三个反引号单独占一行包起来，开头那行可以写上语言名，代码会获得语法高亮。

写这样
```python
def hello():
    print("你好")
```
```bash
mkdir notes
cd notes
```
长这样
def hello():
    print("你好")
mkdir notes
cd notes
反引号在键盘哪？在键盘左上角、数字 1 左边的那个键（` 和 ~ 同一个键），英文输入法下按一下就是反引号，三个连按就是 ```。

表格

用竖线 | 分隔单元格，第二行用减号画出表头分隔线。

写这样
| 姓名 | 职业 |
| --- | --- |
| 福尔摩斯 | 侦探 |
| 华生 | 医生 |
长这样
姓名职业
福尔摩斯侦探
华生医生

控制对齐

在分隔行里加冒号：左边加是左对齐，右边加是右对齐，两边都加是居中。

写这样
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| 文字 | 文字 | 文字 |
长这样
左对齐居中右对齐
文字文字文字

不用费劲对齐竖线，写得歪歪扭扭也能正常渲染，能看清就行。

分割线

单独占一行，写三个或更多的减号。

写这样
上面的内容
···· 空一行 ····
---
···· 空一行 ····
下面的内容
长这样

上面的内容

下面的内容

容易撞车如果减号紧贴在文字下一行，它会把上一行变成二级标题，而不是分割线。所以前后都要空一行，想稳一点就写 ***。

转义字符

如果你就是想显示一个星号，而不是让它变粗体，在符号前面加一个反斜杠 \。

写这样
\*这不会被变成斜体\*
\# 这不是标题
长这样

*这不会被变成斜体*

# 这不是标题

拓展：用 Markdown 写博客

下面这两样不是 Markdown 标准语法，而是静态网站生成器的通用约定。Hexo、Hugo、Jekyll 等常见博客框架都能识别它们——理解了原理，将来换任何平台都能快速上手。

① 文章头部信息（front-matter）

文件最开头，用两行 --- 包起来的那一段，叫做 front-matter，用来告诉博客系统这篇文章的标题、发布时间、标签等元信息。它必须顶格写在文件第一行。

---
title: 我的新文章          # 标题
date: 2026-10-17 20:30:00  # 发布时间，不写则用当前时间
tags: [杂谈]               # 标签，多个写 [杂谈, 折腾]
categories: [随笔]           # 分类
top: true                  # 部分主题支持：加这行可首页置顶
---
# 空一行，下面开始写正文
格式很严格冒号后面要有空格（title: 标题，不是 title:标题）；--- 必须是文件第一行，前面不能有空行或空格。

② 摘要截断标签

博客首页的文章列表通常只展示摘要。想指定摘要在哪里截断，就在该位置单独占一行放一个截断标签，标签上面的内容就是摘要。

不同平台的标签写法略有差别：

  • Hexo 用 <!-- more -->
  • WordPress、Hugo 用 <!--more-->

原理都一样：它本质上是一个只有平台认识、不会显示在正文中的特殊标记（HTML 注释），不是 Markdown 语法，写法必须一字不差。

以 Hexo 为例，完整的样子

---
title: 血字的研究读后感
date: 2026-10-17 20:30:00
tags: [读书, 推理]
---

这是开头的一段引子，会出现在首页摘要里。

<!-- more -->

完整范例

把上面所有东西拼起来，一篇典型的 Markdown 文档大概长这样：

# 贝克街的早晨

伦敦的雾还没散，贝克街 221B 的窗帘已经拉开了。

## 一种观察的方法

福尔摩斯说过一句很有名的话：

> 排除一切不可能的，剩下的即使再不可思议，那也是真相。

这句话听起来像魔法，其实说的是一件很朴素的事 —— **把不确定的东西逐个排除**。

### 具体怎么做

1. 先把所有已知事实列出来
2. 再列出所有可能的解释
3. 最后用事实去筛掉站不住脚的那些

| 步骤 | 要做的事 | 常见错误 |
| --- | --- | --- |
| 一 | 收集事实 | 把猜测当成事实 |
| 二 | 列举可能 | 过早锁定一个答案 |
| 三 | 逐条排除 | 舍不得放弃自己的猜想 |

如果卡住了，回头看看第一步：

- 有哪些「事实」其实只是听说？
- 有哪些细节被自己忽略了？

常见错误 TOP 10

症状原因改法
标题没变成标题，还是一行 # 文字井号后面没空格改成 # 文字
分开写了两行，显示时挤成一行只按了一次回车中间空一行，或行尾加 <br>
星号变成了斜体，但我只想显示星号没转义写成 \*
表格全挤成一行、没变成表格漏了第二行的 | --- | --- |补上分隔行
图片显示不出来，只有个裂图标路径写错 / 文件没放在对应位置 / 大小写不一致核对路径：本地图片确认相对位置，网络图片确认链接能直接打开
文章头部那几行直接显示在正文里了--- 前面有空行或空格（Hexo/Hugo/Jekyll）让 --- 成为文件真正的第一行
摘要截断没生效标签写法和所用平台不匹配Hexo 必须写成 <!-- more -->，注意空格
分割线把上一行变成了大标题减号紧贴文字，没空行前后各空一行
中文全是问号或方块文件不是 UTF-8 编码用编辑器另存为 UTF-8
代码块没高亮，或者格式乱三个反引号没单独占行 / 数量不对开头结尾各三个，各自单独一行
写错了也不要紧Markdown 很宽容。写错一般只是那一段显示得不好看，不会让整篇文档打不开。保存后切到编辑器的预览窗口看一眼，就知道对不对了。
